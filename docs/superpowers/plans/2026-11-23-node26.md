# Node 26 LTS (26.13.1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move every place corgi sets or assumes a Node version from 24.22.3 to Node 26.13.1 LTS. That covers the deployed Cloud Run image, CI, local pins, Node-tied deps and docs. Nightly runtime monitoring must keep matching what is deployed.

**Architecture:** This is a version bump only, with no behaviour change. The production runtime comes from `backend/Dockerfile`, because Cloud Run is image-based and `backend.yml` deploys `:latest`. Hosting serves a static build that CI produces. Each task bumps one layer and proves it with a check that fails before the change and passes after it.

**Tech Stack:** Node 26.13.1 (npm 11.20.0, V8 14.6, ABI 147), `node:26.13.1-alpine` (alpine 3.23), GitHub Actions `actions/setup-node`, Volta, TypeScript 5, Express 4, Vite 6, Vitest 4, Playwright, firebase-tools 15.37.0 (e2e emulators).

## Local Node 26 without changing the Mac

The Mac has only 24.x in Volta. Once package.json pins 26.13.1, a Volta shim would fetch 26 into `~/.volta`, so all local runs bypass Volta:

- Download `node-v26.13.1-darwin-arm64.tar.gz` and `SHASUMS256.txt` from `https://nodejs.org/dist/v26.13.1/`. Check the sha256 and extract into `<worktree>/.local-node26/`. Never `git add` it; stage files by explicit path only. Delete it before the PR.

## Review Focus

1. **OTel/langfuse on 26.** `module.register()` is runtime-deprecated in 26. `initLangfuse()` runs only when LANGFUSE keys are set, so the boot check in Task 1 sets dummy keys to exercise `NodeTracerProvider.register()`. It expects no `DeprecationWarning` on stderr.
2. **Undici 8 `fetch`.** `backend/src/tools/hackernews.ts:25` and `anthropicNews.ts:31` call global `fetch`. Their unit tests run on 26 in Task 3. A live call isn't possible offline, so after deploy the briefing tools are checked in the production smoke step.

Task 1 checks that `/usr/local/bin` in the built image has no `npm`/`npx`, and records whether `corepack` exists. Corepack isn't removed today on 24 either, so that's out of scope.
4. **Nightly check after deploy.** `deployed-node` must print `up to date: production runs v26.13.1`. Task 2 adds a test that pins the same-major compare for a 26 deployment.
5. **The superstatic EBADENGINE warning** in `e2e` `npm ci` must stay a warning and not fail CI. Task 3 confirms `npm ci` exits 0 on 26.

## Post-merge deploy verification (for whoever merges)

Merging deploys production. The following workflows run on push to `main`:

| Workflow | Why it runs | Check |
|---|---|---|
| `Deploy Backend` (`backend.yml`) | `backend/**` changed | Green. Builds the 26 image, pushes `:latest`, deploys `corgi-backend`. |
| `Deploy Frontend` (`frontend.yml`) | `frontend/**` and `frontend.yml` changed | Green. Hosting deploy built on 26. |
| `Deploy Firestore Rules and Indexes` (`firestore-rules.yml`) | the workflow file changed | Green. Redeploys the unchanged rules and indexes, now on pinned Node 26. |

Then:

1. `gh run list --branch main --limit 5` shows all three succeeded.
2. Cloud Run's latest ready revision is new and serving: `gcloud run services describe corgi-backend --region asia-northeast1 --format='value(status.latestReadyRevisionName,status.url)'`. Then `curl -fsS <url>/health` → `{"ok":true}`.
3. Dispatch `Audit (nightly)` with `gh workflow run audit-nightly.yml`. This needs the user's OK, since it is an outward action. Expected:
   - `Deployed backend Node version` logs `up to date: production runs v26.13.1`
   - `Deployed backend image` (Trivy) passes
   - every audit job passes
4. Production smoke test in the app: sign in, send a chat message, and trigger the HN or Anthropic-news briefing tool. This exercises Undici 8 `fetch` against live endpoints. Check Cloud Run logs for `DeprecationWarning` or errors in the first minutes.
5. Rollback: `gcloud run services update-traffic corgi-backend --region asia-northeast1 --to-revisions <previous revision>=100`, then revert the PR.
